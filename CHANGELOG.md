# История работы

## 2026-09-11 — первый день: от идеи до релиза v1.0.0

### Что сделано

**Исследовано**
- Официальный REST API ProPresenter (OpenAPI-спека: openapi.propresenter.com, `swagger.json`),
  живой ProPresenter 20 на Windows, порты 50001/1025, включение через Настройки → Сеть → Network.
- Легаси-протоколы (jeffmikels.github.io/ProPresenter-API) — не используются.
- Почему чистый PWA на GitHub Pages невозможен: mixed content + CORS → нужен локальный мост.

**Построено**
- `server.js` — мост на Node (0 зависимостей): статика + прозрачный прокси `/pp/*`
  + автопоиск порта API + ленивый переподключ к ProPresenter.
- `public/` — веб-пульт (PWA): тёмная тема, мобильный layout.
  Возможности: текущий/следующий слайд (миниатюра, текст, заметки, группа),
  «Вперёд/Назад», переход по ленте слайдов, выбор презентации (🗂 библиотеки
  и плейлисты с миниатюрами, тап = запустить), «Убрать фон», «Выключить экран»
  (красная, как в PP), «Очистить слайд», панель «Слои», бейдж «⏸ вне эфира»,
  синхронизация внешних переключений ~1 с, добавление на главный экран iOS/Android.
- `go/` — мост на Go одним бинарником с вшитым UI (go:embed): Windows/macOS
  (arm64 + amd64), скрипты сборки, понятная ошибка при занятом порте.
- `test/mock.js` — мок API ProPresenter (демо без PP + база для тестов),
  `test/smoke.js` — 16 проверок, `tools/gen-icons.js` — генератор иконок.
- Релиз **v1.0.0** с тремя бинарниками (GitHub Releases).
- Windows: добавлено правило файрвола «ProPresenter Пульт (8080)» (входящий TCP).

### Важные открытия по ProPresenter 20 (задокументировать на будущее)

1. `/v1/presentation/slide_index` **всегда null** — источник правды о живом слайде:
   `/v1/status/slide` (текст + uuid).
2. `status/slide.next` — пустой, «следующий» вычисляем по позиции в колоде.
3. После «Очистить слайд» `/v1/presentation/active` = null — колоду в пульте держим сами.
4. У слайдов колоды нет UUID → индекс ищется сопоставлением текста
   (нормализация `\r`/`\r\n` → `\n`), при дублях (припев) — ближайший к текущей позиции.
5. Живость слайда определяем по uuid из status/slide — слайд может быть без текста (картинки).
6. `GET /v1/look/current` отстаёт от реальности на секунды после PUT — тумблеры слоёв
   оптимистичные, состояние читается при открытии панели.
7. `clear/layer/media` = «убрать фон» (текст остаётся); фон возвращает следующий слайд.
8. Повторный триггер того же слайда не всегда переприменяет фон (особенность PP).

### Исправленные баги (найдены тестом с iPhone 13 Pro)

- Слайд без текста (только картинки) ослеплял пульт → теперь живость по uuid.
- Дубли текста уводили позицию на первое вхождение → матчинг ближайшего.
- Лента пересобиралась каждые ~3 с — тапы по ней терялись → рендер по диффу.
- `scrollIntoView` дёргал страницу вниз на iOS → ручной горизонтальный скролл ленты.
- Двойной тап по «Вперёд» = зум на iOS → `touch-action: manipulation`.
- Опрос откатывал оптимистичное переключение → блокировка 2.5 с после своего триггера.
- Go-бинарник закрывался молча при занятом порте → понятная ошибка + пауза.
